# 🧪 Generate Test Cases — AI 驱动的测试用例生成器

一个AI驱动的后端测试用例生成skill，把需求文档（MD / Word / PDF / Excel / 图片…）自动变成**可直接导入 XMind 的专业测试用例**。它不是让 AI 随便写几条用例，而是强制 AI 按 **10 种测试设计方法**系统性覆盖，并用 **21 项质量指标**在输出前自检生成的用例质量，并同步生成用例质量报告。

---

## 🎯 这个工具解决什么痛点

如果你是测试工程师，下面这些场景应该很熟悉：

| 痛点 | 这个 Skill 怎么解决 |
|------|---------------------|
| **写用例太慢** —— 一个中等需求要写 2~4 小时 | 一次对话输出完整用例集（含前置条件、步骤、预期结果） |
| **容易漏场景** —— 边界、异常、并发、缓存常常想不到 | 10 种设计方法强制叠加，每种方法都必须产出对应用例，漏了会在质量报告里标红 |
| **AI 写的用例太水** —— 只覆盖正向流程，负面用例不足 | 强制负面用例占比 ≥ 30%，不达标自动补 |
| **同样的 bug 反复出现** —— 上次漏掉的，这次还漏 | Bug 反向学习：告诉它「为什么没生成 xxx 用例」，它会分析根因并永久记住 |
| **多人协作风格不统一** —— 每个人写用例的粒度、优先级标准都不一样 | 项目级记忆：术语、模块划分、优先级规则统一复用 |
| **需求含糊不清时不知道怎么办** —— AI 自己瞎猜或者拒绝干活 | 只在关键歧义时打断询问，并把你的决策记下来，下次遇到相同情况自动复用 |
| **输出格式不统一** —— 每次导出都要手动调 | 直接输出符合 XMind 导入规范的 `.xmind` 文件，打开即用 |
| **需求和用例对不上** —— 需求改了不知道哪些用例要改 | 自动生成需求 ↔ 用例双向追溯矩阵（哪条需求被哪几个用例覆盖、覆盖率多少，一目了然） |

**一句话总结：把一个靠谱测试同事的思维方式固化成工作流，让 AI 按同样的标准稳定产出。**

## ✨ 具体功能

### 1. 看得懂各种需求文档

支持以下格式：

- **文本类**：`.md` `.txt` `.rst` `.html`
- **Office**：`.docx` `.xlsx` `.pptx`（内置 Python 脚本抽取文本）
- **PDF**：`.pdf`（pdfplumber 抽取）
- **图片**：`.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp` `.svg`（走多模态，截图原型图也能解析）

### 2. 10 种测试设计方法强制叠加

不是「选一种」，是**每种都要过一遍**，最后去重。这样哪怕需求写得简陋，用例也不会漏层次。

**核心 5 种**

| 方法 | 它具体会做什么 |
|------|---------------|
| 等价类划分 (EP) | 识别出所有有效 / 无效等价类，每类至少 1 个用例 |
| 边界值分析 (BVA) | 对每个数值/长度字段，测上点、离点、内点（比如长度 ≤ 50 的字段，会生成 0、1、50、51、100 这类用例） |
| 参数验证 (PV) | 每个入参都跑一遍：必填、类型、长度、范围、格式 |
| 场景法 (ST) | 按基本流 → 备选流 → 异常流展开业务流程 |
| 错误推测 (EG) | 特殊字符、SQL 注入、XSS、极端值、并发、断网… |

**补充 5 种**

| 方法 | 它具体会做什么 |
|------|---------------|
| 出参验证 (RV) | 对每个响应字段单独写用例，验证字段存在性、类型、取值范围 |
| 业务状态穷举 (BS) | 订单有 6 种状态？那就生成 6 个用例，每个状态都测一遍对应行为 |
| 关联关系验证 (RL) | A 用户的 token 能不能访问 B 用户的资源？资源归属判断是否到位 |
| 数据库验证 (DB) | 操作后校验 DDL 结构（字段、索引）+ DML 数据（记录是否正确写入、更新、删除） |
| Redis 缓存验证 (REDIS) | 缓存是否生成、key 是否正确、TTL 是否合理、更新后缓存是否刷新、删除后缓存是否失效 |

### 3. 21 项质量自检 + 熔断

用例写完后先不急着给你，先自己体检。关键指标：

- ✅ 需求覆盖率 ≥ 95%
- ✅ 需求分支覆盖率 ≥ 90%
- ✅ 负面用例占比 ≥ 30%
- ✅ 优先级分布合理（P0: 10-15%、P1: 30-40%、P2: 20-40%、P3: 10-20%）
- ✅ 10 种设计方法每种都有用例
- ✅ 参数验证 / 出参 / 状态 / 关联 / DB / Redis 都有对应覆盖
- ✅ 模块分布均衡、无重复用例、无凭空编造
- ✅ …

**不达标会自动修正，最多重试 3 次**。最终的质量报告同时输出到聊天窗口 + 文件，哪里不达标一目了然。

### 4. 项目级记忆 / 越用越准

第二次用同一个项目时，它会记住：

- **项目路径**：不用每次问你需求放哪、输出到哪
- **领域术语**：比如「工单」在你项目里具体指什么，「已完结」和「已关闭」的区别
- **模块划分**：跟上次生成的分类保持一致，不会这次叫「用户管理」下次叫「账号模块」
- **优先级习惯**：你偏好的 P0/P1 划分标准
- **歧义决策**：上次遇到「订单取消后多久可以恢复」你选的是「30 分钟内」，这次直接用

### 5. Bug 反向学习

这是我觉得最有用的一个功能。

测试中发现了用例没覆盖到的 bug，直接问：

```
为什么没有生成订单并发支付时扣款两次的用例？
```

它会：

1. 分析 bug 根因（并发 + 幂等 + 金额扣减）
2. 回溯漏掉的设计方法（EG 错误推测 + DB 数据库验证）
3. 补齐这类用例
4. 提出改进建议（比如「业务规则中应补充幂等性要求」）
5. **永久记下来**，下次遇到涉及金额/并发的需求自动覆盖

### 6. 只在真正需要时打断你

很多 AI 工具要么过度提问（什么都要你确认），要么完全不问（自己瞎猜）。这个 Skill 有明确规则：

- 非关键歧义 → 自己按合理假设处理并在用例里标注
- 关键歧义（影响核心业务逻辑） → 打断询问
- 问过一次的 → 记住，不再问第二次

## 🤖 支持哪些 AI IDE

这个 Skill 的核心是 `SKILL.md` + `references/` 里的规则文档 + `scripts/` 里的工具脚本，**本质上是一套提示词工程 + 工具链**，理论上任何支持「自定义 Skill / Agent / 规则文件」的 AI 编程环境都能用：

| 环境 | 支持情况 | 使用方式 |
|------|---------|---------|
| **Kiro** | ✅ 原生支持 | 放到 `~/.kiro/skills/` 即可 |
| **Claude Code (CC)** | ✅ 支持 | 作为 Skill 放到 `~/.claude/skills/` 下 |
| **Cursor** | ✅ 可用 | 把 `SKILL.md` 内容放入 `.cursorrules` 或 Rules 配置 |
| **Cline / Roo Code** | ✅ 可用 | 作为 Custom Instructions 加载 |
| **其他支持系统提示词自定义的 AI IDE** | ✅ 可用 | 只要能加载自定义提示词 + 能执行 Python 脚本 |

**通用要求**：

- Python 3.8+（用于执行 XMind 导出、文档解析脚本）
- 可选依赖（按你的需求文档格式安装）：

```bash
pip install python-docx openpyxl python-pptx pdfplumber
```

## 🚀 怎么用

1. 准备需求文档（随便什么格式）
2. 对 AI 说：

   ```
   帮我生成测试用例
   ```

3. 接下来它会：
   - 首次使用：问你需求目录、输出目录放哪
   - 读取并解析需求文档
   - 按 10 种设计方法生成 + 去重
   - 有关键歧义时问你
   - 质量自检（不达标自动修正）
   - 输出质量报告 + `.xmind` 文件

4. 双击 `.xmind` 文件打开即可

## 🏗️ 工作流程

```
Phase 0: 项目初始化（首次运行，记录路径）
   ↓
Phase 1: 读取需求（自动识别文件格式）
   ↓
Phase 2: 解析需求（10 种设计方法叠加 + 去重）
   ↓
Phase 2.5: 解析确认（需求有明显问题时询问）
   ↓
Phase 2.6: 歧义处理（仅关键歧义）
   ↓
Phase 2.8: 质量预审（21 项自检 + 不达标自动修正 + 质量报告）
   ↓
Phase 3: 生成文档（JSON → XMind）
   ↓
Phase 4: 更新记忆（术语、模块、偏好持久化）
   ↓
Phase 5: 用户反馈学习（Bug 反向学习触发点）
```

## 📁 项目结构详解

```
generate-test-cases/
├── SKILL.md                       # 🎯 Skill 主文件：工作流、规则、用例格式定义
│                                  # 这是 AI 的"说明书"，加载它 AI 就知道怎么干活
│
├── references/                    # 📚 参考规则库（AI 按需加载，不会一次塞爆上下文）
│   ├── TEST-DESIGN-METHODS.md     # 核心 5 种设计方法 (EP/BVA/PV/ST/EG) 的详细规则
│   ├── PARAMETER-VALIDATION.md    # 参数验证方法论：必填、类型、长度、范围怎么测
│   ├── API-DEEP-COVERAGE.md       # 补充 5 种深度覆盖方法 (RV/BS/RL/DB/REDIS)
│   ├── BUSINESS-RULES.md          # 业务测试通用规则（金额精度、时间、并发、幂等…）
│   ├── COMPANY-NOTES.md           # 公司/团队特定注意事项（可按需改成你们的规范）
│   ├── PARSING-RULES.md           # 需求文档解析规则：怎么识别模块、接口、字段
│   ├── TEST-PRIORITY.md           # 优先级定义（P0~P3）+ 回归范围划分标准
│   ├── TRACEABILITY.md            # 需求 ↔ 用例追溯矩阵的生成规范
│   ├── INTERACTION-PATTERNS.md    # 什么时候打断问用户、什么时候自己做决定
│   ├── MEMORY-SCHEMA.md           # .memory/ 下各文件的 JSON 结构定义
│   └── LEARNING-RULES.md          # 自学习规则：什么时候更新记忆、怎么 Bug 反向学习
│
├── scripts/                       # 🔧 工具脚本
│   ├── generate_xmind.py          # 把用例 JSON 转成 .xmind 文件（核心导出）
│   ├── generate_excel.py          # 把用例 JSON 转成 .xlsx（备选格式）
│   ├── extract_text.py            # 从 docx/xlsx/pptx/pdf 中抽取纯文本给 AI 读
│   └── memory_manager.py          # 管理 .memory/ 下的记忆文件（读写/清理/重置）
│
├── .memory/                       # 🧠 运行时记忆（首次运行自动生成）
│   ├── project-context.json       # 项目基本信息：需求目录、输出目录、项目名
│   ├── terminology.json           # 领域术语库：业务名词 → 标准定义的映射
│   ├── generation-history.json    # 生成历史：每次的质量分数、覆盖率、用例数
│   ├── user-preferences.json      # 用户偏好：优先级习惯、模块命名风格等
│   └── ambiguity-decisions.json   # 历史歧义决策：避免重复询问同一个问题
│
├── tmp/                           # 临时文件（用例中间 JSON、解析结果等）
└── .gitignore
```

**文件职责一句话版**：

- `SKILL.md` = AI 的总指挥
- `references/` = 各个领域的专家手册，AI 按需查阅
- `scripts/` = AI 的工具箱，跑具体转换 / 抽取任务
- `.memory/` = AI 的长期记忆

## 📝 输出格式

### XMind 节点结构

```
根节点（项目名称）
└── 模块
    └── tc-p0: 用例标题
        ├── pc: 前置条件（可选）
        ├── 1. 操作步骤
        │    └── 1. 预期结果
        └── 2. 操作步骤
             └── 2. 预期结果
```

### 用例 JSON 字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `模块` | ✅ | 数组，最多 8 层 |
| `用例标题` | ✅ | 动作 + 对象 + 条件/场景 |
| `优先级` | ✅ | P0 / P1 / P2 / P3 |
| `需求ID` | ✅ | 关联的需求标识（用于追溯矩阵） |
| `设计方法` | ✅ | 10 种方法之一或多个 |
| `前置条件` | ❌ | 特定环境准备 |
| `步骤` | ✅ | 操作 + 预期结果数组 |

## 🔧 常用记忆管理命令

| 对 AI 说 | 效果 |
|---------|------|
| `更新术语表` | 重新扫描当前项目，刷新领域术语 |
| `清除记忆` | 重置所有学习数据（慎用） |
| `重置偏好` | 仅重置用户偏好 |
| `重置术语` | 仅重置术语库 |
| `重置歧义决策` | 仅重置历史歧义决策记录 |
| `重置生成历史` | 仅重置生成历史（质量趋势归零） |
| `显示学习记录` | 查看历史生成的质量趋势和当前偏好 |
